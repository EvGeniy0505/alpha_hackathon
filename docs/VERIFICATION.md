# Руководство по проверке

## Запуск

Из корня репозитория:

```bash
docker compose up --build --detach --wait
docker compose ps
```

Контейнер app должен получить статус healthy. Откройте
[localhost:8000](http://localhost:8000) и
[/health](http://localhost:8000/health): ожидается ответ с status=ok.
Требования к окружению и выбор другого порта описаны в [README](../README.md#как-запустить).

## Учётные записи и данные

| Роль | Логин | Пароль |
|---|---|---|
| Клиент | client | client-pass |
| Второй клиент | client2 | client2-pass |
| Сотрудник банка | analyst | analyst-pass |

Десять профилей компаний находятся в [data/clients.json](../data/clients.json).
Для параллельной работы двух ролей используйте разные браузеры или приватное окно.
Все данные вымышлены. Примеры CSV и описание колонок — в [examples](../examples/README.md).

## Основной сценарий

1. Войдите как client и создайте заявку кнопкой «Новая заявка» либо через Пуша.
2. Выберите разовый оборотный кредит: 800 000 рублей на 18 месяцев,
   цель — закупка сырья, обеспечение — без залога.
3. Укажите среднемесячные показатели: выручка 1 500 000 рублей,
   операционные расходы 1 000 000 рублей, другие кредитные платежи 100 000 рублей.
4. Загрузите [выписку](../examples/bank-statements/stable_business_6m.csv).
   Для финансового документа выберите «Декларация УСН» и загрузите
   [пример декларации](../examples/financial-documents/usn_declaration_stable_12m.csv).
5. Отметьте оба согласия, проверьте параметры и сохраните черновик.
6. Откройте сохранённую заявку и отправьте её в банк. Ожидается статус «Одобрено».
7. Примите условия. Ожидается «Выдано», в истории — этапы подписания и выдачи.

Подписание и выдача демонстрационные; юридическая подпись и перевод денег не выполняются.

## Дополнительные сценарии

| Сценарий | Действие | Ожидаемый результат |
|---|---|---|
| Заявка без диалога | После входа нажать «Новая заявка» | Форма открывается без сообщений Пушу |
| Сумма в диалоге | Указать 1 500 000 ₽, в том числе с неразрывными пробелами | Сумма переносится без искажения |
| Уточнение суммы | После суммы вне лимита ввести допустимую сумму цифрами | Пуш принимает исправление |
| Срок без единицы измерения | Для овердрафта выбрать сумму 499 999 ₽, затем ответить 3 или 5 на вопрос о сроке | Число принимается как месяцы; сумма сохраняется |
| Ограничение срока | Для овердрафта ответить 13, затем 5 | Пуш запрашивает допустимый срок, после исправления формирует условия |
| Уточнение банка | В основном сценарии указать другие платежи 0 ₽; отправить, под analyst запросить уточнение; клиенту исправить платежи на 50 000 ₽ и ответить | Заявка проходит manual_review → needs_info → manual_review; аналитик может одобрить |
| Отказ и альтернатива | 600 000 ₽ на 12 месяцев, выручка 110 000 ₽, расходы 10 000 ₽, другие платежи 50 000 ₽; согласие БКИ | Предварительный отказ по денежному потоку и предложение других параметров |
| Доступ по владельцу | После создания заявки client войти как client2 | Заявка первого клиента недоступна |
| Предварительный расчёт | Проверить параметры без сохранения | Новая заявка в списке не создаётся |
| Перезапуск | Сохранить заявку, выполнить docker compose restart app и войти снова | Заявка и события остаются в базе |
| Повторное принятие | Повторить accept для завершённой заявки через API | Ответ 409; повторной выдачи нет |

Подробный проход ручного рассмотрения и примеры значений доступны
в [README](../README.md#что-проверить).

## Автоматические тесты

```bash
python -m unittest discover -s tests -v
node --test tests/*.test.cjs
```

Python-тесты используют стандартную библиотеку; Node.js нужен только для JavaScript-тестов.
Набор содержит 39 Python-тестов и 18 JavaScript-тестов.
Проверяются расчёты и лимиты продуктов, переходы состояний, роли и владельцы,
согласия, хранение данных, HTTP-контракт, конфигурация HTTPS и диалог Пуша.

[Коллекция HTTP-запросов](requests.http) включает 24 запроса: вход, расчёт,
создание и отправку, принятие условий, уточнение и ручное одобрение.
tests/test_delivery.py исполняет эту коллекцию через серверный обработчик и временную SQLite.
tests/test_api.py проверяет HTTP-запросы к отдельному тестовому серверу.

## Границы демонстрации

Проверки компании и БКИ выполняются локальными симуляторами.
Пуш использует сценарный диалог. Скоринг основан на объяснимых правилах,
его балл не является вероятностью дефолта. Ставки и лимиты демонстрационные.
Работа с реальными банковскими системами и платные API не требуются.
SQLite хранится в постоянном томе Docker Compose; ограничения дополнительного
бесплатного облачного запуска описаны в [DEPLOYMENT.md](DEPLOYMENT.md).
