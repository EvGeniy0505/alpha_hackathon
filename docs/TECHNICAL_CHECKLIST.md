## Исправленные расхождения

- Коллекция запросов использовала несуществующий общий пароль demo-pass-2026
  и отклоняемые поля реквизитов внутри анкеты.
- OpenAPI не описывал профиль, реестр компаний и заявки выбранной компании;
  содержал устаревшие продуктовые лимиты, три аккаунта и обязательный комментарий
  при одобрении; не учитывал документы, залог и текущие поля анкеты.
- В модели данных отсутствовали users и clients; ошибочно было написано,
  что отдельной таблицы пользователей нет.
- В README незакрытый details скрывал архитектуру и настройки на GitHub.
- Утверждение старого обзора о невыполненном ТЗ из-за отсутствия ИИ заменено:
  исходный кейс прямо допускает решение без ИИ.

## Что нельзя считать подтверждённым

Доступ к Docker daemon в текущей среде блокируется, Docker Compose не найден.
Поэтому наличие Dockerfile не выдаётся за успешный контейнерный запуск.
До отправки нужно на обычном ПК с работающим Docker выполнить:

```bash
docker compose config --quiet
docker compose up --build --detach --wait
docker compose ps
```

Открыть http://localhost:8000/health и пройти первый сценарий README.
Сохранить заявку, выполнить docker compose restart app, снова войти
и убедиться, что заявка и события остались. Затем записать окончательный
commit hash в форму сдачи. Для публичного репозитория отдельный доступ жюри
не нужен. Облачная публикация не является обязательной частью страницы 7.

Текущие ограничения MVP: один экземпляр приложения с SQLite,
демонстрационная аутентификация, локальные симуляторы ФНС/БКИ,
имитация подписания и выдачи. Эти упрощения явно описаны и не требуют
платных или корпоративных систем.
