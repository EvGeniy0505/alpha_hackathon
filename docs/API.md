# HTTP API

Сервер: http://localhost:8000. Машиночитаемый контракт: [openapi.json](openapi.json),
на работающем сервере — /openapi.json. Коллекция: [requests.http](requests.http).

Все тела запросов и ответов — JSON, кроме статических страниц.
Для POST/PUT нужен Content-Type: application/json; тело — до 64 КиБ.
Вход создаёт HttpOnly, SameSite=Strict cookie session на 8 часов.
Cookie передаётся автоматически браузером или cookie jar HTTP-клиента.
Host проверяется по ALLOWED_HOSTS. Для записи Origin, если передан,
должен соответствовать этому приложению. Внешний CORS не включён.

## Анкета и профиль

company_name, tax_id, business_months и контакты принадлежат профилю компании.
В теле заявки эти поля не принимаются. Минимальная анкета:
product_id, amount, term_months, purpose, revenue_monthly, expenses_monthly,
existing_payment. Полный состав дополнительных полей — ApplicationInput в OpenAPI.
Проверяются лимиты выбранного продукта, целые сроки, конечные числа, типы согласий.
Неизвестные поля отклоняются. Для залоговых продуктов требуется подходящее обеспечение.

Веб-клиент передаёт параметры документов и согласия явно.
Значения bank_account и bank_report означают локальные синтетические источники банка.
Для отсутствующих необязательных полей применяются описанные в OpenAPI значения по умолчанию.
Исходный CSV не загружается на сервер: браузер передаёт агрегаты и имя файла.

## Изменение состояния

При submit обязательны consent=true и bki_consent=true.
При повторной отправке после needs_info требуется clarification от 10 символов.
Неблокирующий результат после уточнения возвращается сотруднику на manual_review.
Автоматический отказ нельзя отменить через decision.
Для reject и request_info нужен комментарий от 10 до 2000 символов.
Для approve комментарий можно не передавать либо оставить пустым.
accept работает один раз и не выполняет реальный перевод денег.

Сессии, заявки и их события хранятся в SQLite на именованном Docker-томе.
Изменение заявки и запись событий — одна транзакция.
GET и preview не создают заявки. Повторный POST создания создаёт ещё один черновик:
универсальная идемпотентность создания в MVP не реализована.

## Ошибки

| Код | Значение |
|---|---|
| 400 | Некорректный JSON, поле, согласие или данные |
| 401 | Нет сессии, истёк срок или неверный пароль |
| 403 | Недопустимые роль, Host или Origin |
| 404 | Неизвестный маршрут, компания или недоступная заявка |
| 405 | Неподдерживаемый метод для маршрута заявки |
| 409 | Недопустимый переход состояния или конфликт ИНН |
| 413 | Тело запроса превышает 64 КиБ |
| 415 | Content-Type отличается от application/json |
| 500 | Внутренняя ошибка |

Тело ошибки: {"error":"Понятное сообщение"}.
Чужая заявка для клиента отвечает 404, чтобы не раскрывать её существование.
