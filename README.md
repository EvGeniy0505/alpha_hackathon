# Ясно — кредит с понятным решением

Первая локальная MVP для кейса «Умный кредитный кабинет предпринимателя»: клиент выбирает продукт, сохраняет заявку, получает объяснимый результат и продолжает процесс внутри кабинета. Сотрудник банка рассматривает пограничные случаи и запрашивает уточнения.

Репозиторий: [EvGeniy0505/alpha_hackathon](https://github.com/EvGeniy0505/alpha_hackathon).

## Три отличия

1. **«Что изменить?»** Подбирает меньшую сумму или больший срок, при которых результат учебной политики улучшается. Все кандидаты повторно проходят те же проверки. Неизвестная компания и серьёзная просрочка не исчезают от изменения суммы. Исходная заявка не меняется без действия клиента.
2. **«А если выручка упадёт?»** Сравнивает исходный расчёт со снижением выручки на 10% или 20%. Расходы и текущие кредитные платежи фиксированы. Это сценарий чувствительности, не прогноз доходов.
3. **«Уточнение вместо тупика».** Аналитик выбирает шаблон вопроса, редактирует его и отправляет клиенту. Клиент отвечает в той же заявке; история, данные и следующий ответственный видны в кабинете.

## Клонирование

```bash
git clone https://github.com/EvGeniy0505/alpha_hackathon.git
cd alpha_hackathon
```

## Запуск

Нужен Python **3.12.10**. Внешних Python- и JavaScript-пакетов нет, `pip install` и сборка фронтенда не нужны.

```bash
python server.py
```

Откройте http://localhost:8000. На Windows при необходимости используйте `py -3.12 server.py`.

Единый контейнерный запуск, если установлен Docker с Compose:

```bash
docker compose up --build
```

Остановка: `docker compose down`. Именованный том `credit-data` сохраняет базу между запусками. Не добавляйте `-v`, если данные нужно сохранить. Для первого запуска Docker необходим интернет, чтобы скачать базовый образ; работа приложения после установки автономна.

| Учётная запись | Возможности |
|---|---|
| `client` | Первый клиент: свои заявки, пересчёт, отправка, ответ, имитация принятия предложения |
| `client2` | Второй клиент: проверка изоляции чужих заявок |
| `analyst` | Сотрудник банка: список всех заявок, ручное решение, запрос уточнения |

Общий учебный пароль: **`demo-pass-2026`**. Пользователь `analyst` имеет роль API `bank`. Вход демонстрационный; это не промышленная система идентификации.

## Что уже работает

- Два продукта с разными лимитами, сроками и условными ставками.
- Черновики и редактирование до отправки; после запроса банка можно дополнить данные.
- Локальные симуляторы проверки компании и кредитной истории.
- Отдельные функции скоринга и кредитного решения: одобрение, ручное рассмотрение, отказ.
- Комментарий аналитика, повторная проверка уточнений, история переходов.
- Принятие одобренных условий с явно обозначенной имитацией подписи и выдачи.
- SQLite, сессии, проверка ролей и владельца заявки на сервере, атомарные переходы.
- Запрет повторной отправки/выдачи и обхода отказа через ручное одобрение.

## Быстрая проверка

1. Войдите как `client`. Выберите пример «Одобрение: стабильный бизнес».
2. Нажмите «Проверить параметры», затем «Выручка −20%». Исходные поля не должны измениться.
3. Сохраните черновик, обновите страницу и откройте его слева: данные остаются.
4. Отправьте заявку, получите одобрение и нажмите кнопку имитации выдачи. В истории появятся проверка, одобрение, подпись и выдача.
5. Создайте пример «Ручная проверка: молодой бизнес» и отправьте. Выйдите, войдите как `analyst`, откройте заявку, выберите шаблон вопроса и запросите уточнение.
6. Вернитесь в `client`, откройте эту заявку, заполните ответ от 10 символов, отправьте. В `analyst` примите решение с обоснованием от 10 символов. Клиент увидит актуальный результат.
7. Создайте пример отказа. Его нельзя принять к выдаче или переопределить ручным одобрением.
8. Войдите как `client2`: заявки первого клиента не видны.

**Сценарий для «Что изменить?»**: выберите стабильный бизнес; поставьте выручку **60 000**, расходы **10 000**, текущие платежи **0**, сумму **600 000**, срок **12**. Проверьте параметры: исходный платёж не помещается в поток, но система предложит допустимый вариант. Нажмите «Подставить и проверить». Изменение срока влияет и на общую выплату; меньший платёж не означает более дешёвый кредит.

**Стресс с изменением результата**: стабильный бизнес, выручка **100 000**, расходы **10 000**, текущие платежи **0**, сумма **600 000**, срок **12**. Базовый расчёт одобряется; при снижении выручки на 20% потребуется ручное рассмотрение.

Синтетические данные находятся в `data/demo_profiles.json`. ИНН имеют лишь подходящий формат: они выдуманы, контрольная сумма не проверяется. Только три записи известны симулятору; неизвестные ИНН не дают автоматического одобрения.

## Проверки

```bash
python -m unittest discover -s tests -v
node --check static/app.js
```

Node нужен только для необязательной проверки синтаксиса JavaScript. Для работы приложения он не используется.

`tests/test_scoring.py` проверяет расчёты, границы, неизвестные проверки и альтернативы. `tests/test_api.py` поднимает временный HTTP-сервер и SQLite: проверяет все исходы, уточнение, владение, параллельную отправку, сессии, сохранность и отсутствие записи при пересчёте.

В среде подготовки выполнены HTTP-тесты и тесты расчётов. Docker здесь не установлен; сборку и запуск контейнера необходимо проверить на второй машине. Полный визуальный прогон браузера не завершён из-за тайм-аута инструмента. Облачное размещение не выполнялось.

## Конфигурация

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `HOST` | `127.0.0.1` | Интерфейс локального сервера; в контейнере `0.0.0.0` |
| `PORT` | `8000` | Порт |
| `DB_PATH` | `runtime/credit.db` | Файл SQLite; в контейнере `/app/runtime/credit.db` |
| `DEMO_PASSWORD` | `demo-pass-2026` | Общий пароль демо-ролей |
| `ALLOWED_HOSTS` | `localhost,127.0.0.1,::1` | Разрешённые имена Host без порта, через запятую |

Compose публикует порт только на `127.0.0.1`. База приложения создаётся при первом запуске. Исходный архив не содержит рабочих заявок, паролей пользователей или сессионных токенов.

## Файлы и архитектура

| Файл | Ответственность |
|---|---|
| `server.py` | HTTP, валидация, роли, SQLite, переходы заявки |
| `scoring.py` | Продукты, симуляторы, платёж, баллы, решение, альтернатива |
| `static/` | HTML/CSS/JS без зависимостей |
| `docs/ARCHITECTURE.md` | Схемы, модель данных, допущения |
| `docs/openapi.json` | OpenAPI 3.1, также доступен по `/openapi.json` |
| `docs/requests.http` | Коллекция HTTP-запросов с cookie-сессией |
| `PLAN_4_DAYS.md` | Задачи ML/backend/frontend, контрольные точки и защита |
| `THIRD_PARTY_NOTICES` | Компоненты и имитации |

Один процесс обслуживает UI и API; бизнес-правила вызываются как Python-функции. Вызовы не зависят от платных ресурсов и банковских систем. UI обновляет данные раз в 10 секунд, не перезаписывая редактируемую форму.

## Границы первой версии

Ставки, пороги, компании, проверки и решения выдуманы. Балл 0–100 — индекс правил, **не вероятность дефолта и не обученная ML-модель**. LLM, внешние датасеты, ФНС и БКИ не подключены. Подпись не имеет юридической силы, деньги не переводятся. Вводите только синтетические данные.

`http.server` и общие демо-пароли предназначены для локального прототипа; [документация Python](https://docs.python.org/3.12/library/http.server.html) не рекомендует этот сервер для промышленной эксплуатации. Не открывайте эту сборку напрямую в интернет. Для пилота нужны полноценная аутентификация, TLS, веб-сервер для эксплуатации, ограничение запросов, мониторинг и резервное копирование. SQLite рассчитан на одну реплику; горизонтальное масштабирование здесь не реализовано.

Перед сдачей проверьте Docker из чистого клона. Для сдачи зафиксируйте финальный тег/commit hash и предоставьте жюри доступ `alfa-hack-2026` к приватному репозиторию. Не представляйте синтетические проверки как проверку модели на реальных кредитных данных.
