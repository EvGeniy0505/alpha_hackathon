# Ясно — кредит с понятным решением

Первая локальная MVP для кейса «Умный кредитный кабинет предпринимателя»: клиент выбирает продукт, сохраняет заявку, получает объяснимый результат и продолжает процесс внутри кабинета. Сотрудник банка рассматривает пограничные случаи и запрашивает уточнения.

Репозиторий: [EvGeniy0505/alpha_hackathon](https://github.com/EvGeniy0505/alpha_hackathon).

## Три отличия

1. **«Что изменить?»** Подбирает меньшую сумму или больший срок, при которых результат учебной политики улучшается. Все кандидаты повторно проходят те же проверки. Неизвестная компания и серьёзная просрочка не исчезают от изменения суммы. Исходная заявка не меняется без действия клиента.
2. **Подбор продукта и обеспечения.** Каталог включает оборотные, инвестиционные и специализированные инструменты. Пошаговый помощник предлагает подходящий вариант, а залог или поручительство влияют на расчётную ставку и условия проверки, но не заменяют оценку денежного потока.
3. **«Уточнение вместо тупика».** Аналитик выбирает шаблон вопроса, редактирует его и отправляет клиенту. Клиент отвечает в той же заявке; история, данные и следующий ответственный видны в кабинете.

## Клонирование

```bash
git clone https://github.com/EvGeniy0505/alpha_hackathon.git
cd alpha_hackathon
```

## Запуск

Нужен Python **3.12.10**. Внешних Python- и JavaScript-пакетов нет, `pip install` и сборка фронтенда не нужны.

```bash
python server.py
```

Откройте http://localhost:8000. На Windows при необходимости используйте `py -3.12 server.py`.

Единый контейнерный запуск, если установлен Docker с Compose:

```bash
docker compose up --build
```

Остановка: `docker compose down`. Именованный том `credit-data` сохраняет базу между запусками. Не добавляйте `-v`, если данные нужно сохранить. Для первого запуска Docker необходим интернет, чтобы скачать базовый образ; работа приложения после установки автономна.

| Учётная запись | Пароль | Возможности |
|---|---|---|
| `client` | `client-pass` | Первый клиент: профиль компании и свои заявки |
| `client2` … `client10` | `client2-pass` … `client10-pass` | Ещё девять клиентов с отдельными профилями и заявками |
| `analyst` | `analyst-pass` | Сотрудник банка: заявки, фильтры, ручные решения и реестр клиентов |

Пользователь `analyst` имеет роль API `bank`. Пароли хранятся в SQLite в виде PBKDF2-хешей; исходные тестовые реквизиты используются только для первичного заполнения локальной базы.

## Что уже работает

- Одиннадцать видов финансирования с разными лимитами, сроками, ставками и условиями рассмотрения.
- Пошаговый помощник с возвратом к предыдущему вопросу и применением рекомендованного продукта.
- Учёт обеспечения с консервативной оценкой ликвидной стоимости; отдельная поддержка поручительства Корпорации МСП / РГО.
- Финансовые показатели задаются как среднемесячные за последние 6 или 12 полных месяцев.
- Банковская выписка загружается в CSV и сворачивается в проверяемые показатели: среднемесячные и минимальные поступления, остаток, дни в минусе, регулярность налоговых платежей, сезонность и доля крупнейшего контрагента. Исходный файл в базу не записывается.
- Бухгалтерская отчётность или налоговая декларация загружается как сводный CSV; система сопоставляет подтверждённую выручку и прибыль с данными заявки и выписки.
- С согласия клиента формируется синтетический кредитный отчёт БКИ по ИНН. Действующие обязательства из отчёта участвуют в расчёте долговой нагрузки и DSCR.
- В кабинете показаны этапы «Документы → Проверка → Решение → Предложение и выдача» и отдельный список документов, которых не хватает для решения.
- Аналитик может одобрить заявку без комментария; при запросе уточнения или отказе понятное пояснение клиенту остаётся обязательным.
- Готовые синтетические CSV находятся в `examples/bank-statements/` и `examples/financial-documents/`.
- Отдельные таблицы пользователей и клиентов: ИНН, вид организации, возраст бизнеса, контакты, отрасль и средняя выручка за шесть месяцев.
- Редактируемый профиль компании клиента; постоянные сведения в заявке доступны только для чтения.
- Реестр десяти клиентов для сотрудника банка, переход к заявкам конкретного клиента, поиск по компании/ИНН и фильтры по статусам.
- Черновики и редактирование до отправки; после запроса банка можно дополнить данные.
- Локальные симуляторы проверки компании и кредитной истории.
- Отдельные функции скоринга и кредитного решения: одобрение, ручное рассмотрение, отказ.
- Комментарий аналитика, повторная проверка уточнений, история переходов.
- Принятие одобренных условий с явно обозначенной имитацией подписи и выдачи.
- SQLite, сессии, проверка ролей и владельца заявки на сервере, атомарные переходы.
- Запрет повторной отправки/выдачи и обхода отказа через ручное одобрение.

## Быстрая проверка

1. Войдите как `client`, откройте помощник выбора кредита и пройдите вопросы с возвратом на предыдущий шаг.
2. Выберите продукт и обеспечение, заполните финансы за 6 или 12 месяцев, загрузите выписку и финансовый документ, дайте согласие на получение кредитного отчёта и нажмите «Проверить параметры».
3. Проверьте рассчитанные DSCR, сезонность, концентрацию на крупнейшем контрагенте и расхождения выручки между формой и документами. При отказе или ручном рассмотрении система покажет, каких документов не хватает и что можно улучшить.
4. При отказе проверьте предложенные изменения суммы/срока и альтернативные продукты: исходная заявка не меняется без нажатия кнопки применения.
5. Сохраните черновик, обновите страницу и откройте его слева: данные остаются.
6. Отправьте заявку с результатом ручной проверки. Войдите как `analyst`, откройте её, выберите шаблон вопроса и запросите уточнение.
7. Вернитесь в `client`, ответьте на запрос. В `analyst` примите решение с обоснованием; клиент увидит актуальный результат.
8. Войдите как `client2`: заявки первого клиента не видны.

**Сценарий для «Что изменить?»**: выберите стабильный бизнес; поставьте выручку **60 000**, расходы **10 000**, текущие платежи **0**, сумму **600 000**, срок **12**. Проверьте параметры: исходный платёж не помещается в поток, но система предложит допустимый вариант. Нажмите «Подставить и проверить». Изменение срока влияет и на общую выплату; меньший платёж не означает более дешёвый кредит.

Данные десяти клиентов и их тестовые реквизиты входа находятся в `data/clients.json`. ИНН выдуманы и имеют только подходящий формат.

## Проверки

```bash
python -m unittest discover -s tests -v
node --check static/app.js
```

Node нужен только для необязательной проверки синтаксиса JavaScript. Для работы приложения он не используется.

`tests/test_scoring.py` проверяет расчёты, границы, неизвестные проверки, альтернативы, БКИ, DSCR, сезонность и концентрацию. `tests/test_api.py` поднимает временный HTTP-сервер и SQLite: проверяет все исходы, комплект документов, согласие на БКИ, обязательное обеспечение, уточнение, владение, параллельную отправку, сессии, сохранность и отсутствие записи при пересчёте.

В среде подготовки выполнены 32 HTTP-теста и теста расчётов, проверка синтаксиса JavaScript и визуальный прогон клиентского и банковского кабинетов. Docker здесь не установлен; сборку и запуск контейнера необходимо проверить на второй машине. Облачное размещение не выполнялось.

## Конфигурация

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `HOST` | `127.0.0.1` | Интерфейс локального сервера; в контейнере `0.0.0.0` |
| `PORT` | `8000` | Порт |
| `DB_PATH` | `runtime/credit.db` | Файл SQLite; в контейнере `/app/runtime/credit.db` |
| `ALLOWED_HOSTS` | `localhost,127.0.0.1,::1` | Разрешённые имена Host без порта, через запятую |

Compose публикует порт только на `127.0.0.1`. База приложения создаётся при первом запуске. Исходный архив не содержит рабочих заявок, паролей пользователей или сессионных токенов.

## Файлы и архитектура

| Файл | Ответственность |
|---|---|
| `server.py` | HTTP, авторизация, профили клиентов, роли, SQLite, переходы заявки |
| `data/clients.json` | Первичное заполнение десяти клиентов и тестовые реквизиты входа |
| `scoring.py` | Продукты, симуляторы, платёж, баллы, решение, альтернатива |
| `static/` | HTML/CSS/JS без зависимостей |
| `docs/ARCHITECTURE.md` | Схемы, модель данных, допущения |
| `docs/openapi.json` | OpenAPI 3.1, также доступен по `/openapi.json` |
| `docs/requests.http` | Коллекция HTTP-запросов с cookie-сессией |
| `PLAN_4_DAYS.md` | Задачи ML/backend/frontend, контрольные точки и защита |
| `THIRD_PARTY_NOTICES` | Компоненты и имитации |

Один процесс обслуживает UI и API; бизнес-правила вызываются как Python-функции. Вызовы не зависят от платных ресурсов и банковских систем. UI обновляет данные раз в 10 секунд, не перезаписывая редактируемую форму.

## Границы первой версии

Ставки, пороги, компании, проверки и решения выдуманы. Балл 0–100 — индекс правил, **не вероятность дефолта и не обученная ML-модель**. LLM, внешние датасеты, ФНС и БКИ не подключены. Подпись не имеет юридической силы, деньги не переводятся. Вводите только синтетические данные.

`http.server` и общие демо-пароли предназначены для локального прототипа; [документация Python](https://docs.python.org/3.12/library/http.server.html) не рекомендует этот сервер для промышленной эксплуатации. Не открывайте эту сборку напрямую в интернет. Для пилота нужны полноценная аутентификация, TLS, веб-сервер для эксплуатации, ограничение запросов, мониторинг и резервное копирование. SQLite рассчитан на одну реплику; горизонтальное масштабирование здесь не реализовано.

Перед сдачей проверьте Docker из чистого клона. Для сдачи зафиксируйте финальный тег/commit hash и предоставьте жюри доступ `alfa-hack-2026` к приватному репозиторию. Не представляйте синтетические проверки как проверку модели на реальных кредитных данных.
